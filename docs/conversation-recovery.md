# 对话暂停与连接恢复

Windows 命令通过 `assets/windows-command.ps1` 管理。管理进程在启动 shell 前将自身加入带有 `KILL_ON_JOB_CLOSE` 的 Job Object；父 shell 提前退出也不会丢失子进程归属。暂停或超时终止管理进程，Windows 随之终止该 Job 中的后代进程。启动 Job 失败时不执行命令。

非交互命令的标准输入立即关闭，输出和退出码分别保留。普通前台命令保留 120 秒超时。前台取消仍等待真实退出及输出流关闭，避免在旧命令仍可能写文件时启动新一轮。

需要启动开发服务等后台工作时，调用 `run_command` 并传入 `background: true`。返回的 `command_id` 可交给 `command_status` 查询状态和限长输出，或交给 `stop_command` 停止。句柄只允许创建它的任务作用域操作。后台命令没有前台的 120 秒限时，其输出保留限长尾部；任务完成或暂停时自动回收。

取消超过 5 秒仍未结束时，任务报告清理失败并显示“重试停止”。此时保留执行对象和追踪记录，阻止启动新一轮。只有真实结束后才报告取消成功。重启后加载的历史快照不保留清理错误，因为旧的内存任务已经不存在。

网页的消息连接每 10 秒接收一次显式心跳。30 秒没有消息或心跳会重建连接，并通过 HTTP 拉取会话状态。暂停/继续应答也返回完整快照；快照的服务实例标识和版本号避免旧状态覆盖新状态。侧栏请求成功不会将断开的消息连接标成正常。导航离开的会话和已替换连接的迟到事件会被忽略。

相关回归：

- `scripts/test-command-lifecycle.mjs`：在 Windows 和 POSIX 上验证输出、EOF、退出码、父进程先退出、暂停后无延迟写入、后台句柄归属、正常完成回收、超时与清理失败。
- `scripts/test-web-recovery.mjs`：执行实际网页函数，验证暂停应答、HTTP 恢复、心跳超时、快照乱序和导航竞态。

两项测试已纳入 `npm test`。Windows 回归需要在 Windows Node 下运行，不能仅由 WSL 中的 Linux Node 代替。更新全局 npm 安装并重新启动后台服务后，已运行的服务才会使用修复后的代码。
