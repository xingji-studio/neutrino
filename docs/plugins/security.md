# 权限与执行边界

## 三类插件

声明式插件只有主题、文本、skill、提示词或静态 UI 定义，不执行 Agent 后端脚本。浏览器 HTML 视图仍含可执行代码，但使用独立的 iframe 与受限消息接口。

默认代码插件在私有进程内的 QuickJS VM 中执行。没有 Node 的 process、require、文件系统、全局 fetch 或任意模块解析。`require('@xingjisoft/neutrino/plugin')` 只返回无副作用的 definePlugin 辅助函数；其他依赖需预先打包。宿主 API 是唯一外部效果入口。

native 插件是完全信任的本机代码。它能绕开 SDK 直接访问文件、网络、环境变量和进程。子进程提供崩溃、超时和清理边界，不提供操作系统安全沙箱。启用需要对精确包散列的明确信任；新版本代码变化后需重新授予。只读或限定写入路径的子任务不执行原生工具。

## 权限清单

| 权限 | 用途 |
| --- | --- |
| tools.register / commands.register | 注册模型工具 / 用户命令 |
| prompts.contribute | 提示词片段与 skill |
| hooks.register | 注册事件或流程钩子 |
| ui.contribute | 页面、组件与主题 |
| conversation.read | 浏览器视图读取当前会话投影 |
| composer.read / write / submit | 读取草稿 / 修改草稿 / 提交草稿 |
| filesystem.read / write | 通过宿主读文件与目录 / 写文件 |
| network | 通过宿主进行 HTTP GET |
| process | 通过宿主执行命令 |
| storage | 读写本插件的 JSON 数据 |

启用受限插件即启用清单中展示的能力。每次调用还必须满足回调自己的 effects、当前 TaskScope、原审批策略和预算。声明权限不等于每次外部操作自动获准；例如读工作目录外的文件仍经过原审批入口。

## 数据流

```text
模型选择工具
→ 参数 Schema 和角色检查
→ tool.before 收窄决策
→ 现有风险评估和审批
→ 插件执行回调
→ 每项实际宿主操作再检查 effects、权限、任务范围与风险
→ 原审批入口
→ TaskRuntime 执行与记录
```

纯工具不能调用文件或网络 API。一个只读工具不能靠命令执行获得写权限。子任务继承父任务限制，并可进一步收窄。跨插件服务不能增加调用方的外部效果。事件和钩子不提供文件、网络和进程效果。

## 包与浏览器

包禁止路径逃逸、符号链接和特殊文件，有文件数及大小上限。更新复制到新目录，校验完整性后再切换指针。安装不执行 npm 生命周期脚本，不从工作区文件自动启用代码。发现安装内容被修改后，宿主拒绝激活；重新安装可修复。

插件管理 API 位于现有登录检查之后，写操作继续检查同源。浏览器只读取清单声明的 view、entries.web 和 webAssets，不提供任意包文件读取接口。

iframe 不具有同源身份，CSP 禁止直接联网；消息根据窗口身份、随机 nonce、当前会话和权限进行校验。API 不暴露宿主 API Key、登录凭据、审批按钮或原始 App 对象。切换对话时释放旧视图，草稿写入使用 revision，避免过期编辑覆盖新输入。

受限执行依赖 JavaScript 引擎、Node 和浏览器的正确实现，不等于抵御所有引擎漏洞的操作系统隔离。对于不愿信任的本机代码，不启用 native 模式。

插件命令的 JSON 参数始终按数据处理。参数中出现“无需审批”或完整信任短语，不会成为跳过审批的用户授权；真实外部操作仍使用当前审批策略。
