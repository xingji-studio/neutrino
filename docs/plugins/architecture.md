# 架构、作用域与生命周期

## 组成

`src/plugins/types.ts` 是无应用启动副作用的公开 Agent SDK。`validation.ts` 校验包和配置，`manager.ts` 管理安装状态，`package.ts` 处理离线包，`host.ts` 管理回合注册表与子进程，`runner.ts` 是私有脚本进程，`session.ts` 是终端和 Web 共用的接入层。

现有终端和 Web 保留各自的输入、渲染及会话对象。两者通过 `runPluginTurn()` 创建相同的插件组合，工具发现、插件执行、提示词片段、执行策略和证据账本使用同一层逻辑。`executeTool()` 和现有工具定义函数保留为兼容入口；新增插件工具经注册表分发，内置工具继续保持原行为。

```text
CLI / Web API / TUI 管理器
  → 受锁保护的插件状态与不可变包目录
  → 每回合 PluginHost
      → 工具 / 命令 / 提示词 / Skill / UI / 钩子注册表
      → 每个代码插件一个私有进程
          → QuickJS（默认）或明确信任的 Node ESM
      → 宿主能力桥接
          → 当前 TaskScope → 风险评估 → 原审批入口 → TaskRuntime 证据
```

浏览器读取 UI 清单时不会激活后端插件。HTML/JS 视图运行在独立 opaque-origin iframe，通过有能力检查的消息接口访问宿主。

## 状态布局

默认位于 `~/.neutrino/plugins`：

```text
state.json                         # version、revision、包指针、各 profile 配置
packages/<id>/<version>-<hash>/     # 安装时复制的包，不就地更新
data/<id>/<key>.json               # 插件持久数据
.lock/                            # 短期管理事务锁
```

`NEUTRINO_HOME` 可选择独立的 Neutrino 用户数据目录；`NEUTRINO_PLUGIN_HOME` 单独覆盖插件目录。测试应使用临时目录，不修改真实用户安装。

管理写操作使用互斥锁、revision 检查和临时文件 rename。Web 保存携带读取时的 revision，并发修改返回 409，用户刷新后重试。安装前校验路径与清单，复制后再次校验完整性。

## 作用域

启用状态按 profile 保存。项目覆盖层使用规范化的真实绝对目录作为键，覆盖同 profile 的默认启用状态，并合并插件配置。项目配置来自用户通过管理器的明确操作，仓库内的任意文件不会自行启用代码。

每个回合创建一次 PluginHost。它固定已启用的包、配置和组件选择，保存插件 ID、版本、完整性散列和配置快照。该组合通过 `TaskRuntime.plugins` 由主 Agent、Pro 和子 Agent 共享。子 Agent 保留自己的角色、runId、AbortSignal 和权限，受限工具集合在子作用域内再次筛选。

终端拥有的会话在终端进程加载后端插件；后台 Web 拥有的会话在后台进程加载。浏览器不运行 Agent 后端代码。插件没有隐式的机器级常驻实例；文件监听等资源应在 activate 注册清理函数，随回合结束释放。

## 生命周期

1. 读取已启用的安装记录，解析必需依赖与兼容的可选依赖。
2. 按依赖顺序校验完整性、API 版本、Profile、配置和原生信任。
3. 启动代码插件进程，执行 `activate(ctx)`，收集有数量上限的注册项。
4. 校验注册项、权限、重复名称和资源路径；激活失败则撤销该插件的贡献，跳过依赖它的插件。
5. 发布 `turn.started`，执行普通回合或 `/plugin` 用户命令。
6. 发布 `turn.finished`，按逆序释放 effect 和插件进程。

`activate()` 期间注册贡献；激活完成后注册表固定。每项注册返回 `dispose()`。注册表与执行回调由同一实例拥有，卸载不会残留全局工具。

QuickJS 每个执行片段有 CPU 中断限制，内存上限 32 MiB。插件回调在没有宿主操作等待时默认 15 秒超时。等待宿主审批时暂停该计时，仍受任务取消和任务预算控制。清理最多等待一秒，然后结束进程。

宿主操作串行处理，避免一个插件中的 `Promise.all` 覆盖待处理审批。回调必须 await 宿主操作；提前返回会取消在途操作并报告错误。每回调最多 256 个宿主调用、64 个待处理调用。

## 会话和恢复

`task_run` 的可选字段记录插件版本、错误、动态 UI 元数据及最近的提示词组装。任务 journal 保留插件组合和模型可见的片段。工具结果始终保留文本形式，因此插件缺失时仍能阅读历史。

旧会话不要求迁移为新格式。恢复会话不会调用已保存的插件处理函数或重放工具账本。新回合使用当前已启用的组合。精确重建执行环境时，应恢复记录中的插件版本、散列与配置，并人工发起新的执行。
