# Token 与复杂 DAG 开销优化

上一轮四场景三轮活动中，Fast 在 8 对完整合格配对中的 7 对消耗更多 Token；四路并行任务的 Fast 规划中位耗时为 38.60 秒，Standard 为 16.46 秒。另有三次 shell 调用进入人工审批、两次成功写入夹具目录外。原活动与失败记录保留在 `fast-stability-*` 文件中。

本轮改动不调整供应商模型、Max 档位、上下文容量、输出预算、任务配额、审批票数或原始外部验收要求。历史快照和改动前文件指纹见 `fast-efficiency-before-manifest.json`。

## 规划

新增 `type: tasks` 的共享字段传输。相似任务的验收标准、报告契约和访问类型只传一次；运行时逐个复制共享字段、合并各自的显式字段，再经过原有权限、依赖、任务数量和循环检查。旧 JSONL 和 single 声明继续兼容。

每个普通工作任务仍创建自己的独立验证者；显式独立检查仍直接执行一次；失败恢复不允许单任务声明替换已有状态。规划提示要求完整任务边界和明确的源文件分工，避免在规划时重复原始请求、设计实现、生成冗长取证清单。没有缩短模型推理预算或限制实际必要检查。

## 证据传递

原来，下游上下文同时包含工作产物、完整验证报告、相同工具记录和完整运行快照，正文与元数据多次重复。本轮把它们组织为：

- 保留每份依赖产物的实际结论、报告、假设、未解决项、证据 ID 和版本。
- 验证覆盖记录保留明确布尔结果、版本绑定、未解决项和证据引用。
- 小于等于 16,000 字节的工具记录整段原样内联，避免为少量原始资料增加检索往返。较大记录提供 ID、状态、名称、调用者说明、参数哈希和结果长度索引；通过只读 `read_task_evidence` 取回原始完整记录或精确版本的产物。字节阈值只决定表示方式，不裁剪证据、不降低上下文或输出预算。
- 查询视图允许本任务直接依赖、匹配已记录输入版本的祖先依赖及其独立验证者；不会根据报告声称的 ID 扩大视图。最终审查可读取本次运行的完整记录。未知 ID、超出视图的 ID 和失效版本不会被当作有效证据返回。验证覆盖保留真实报告，避免只留下布尔结果而迫使下游重新查证。
- 持久化和界面快照仍保留全部原始数据。查询返回原文，不做模型摘要、裁剪或替换；原始源文件检查和必要测试仍必须执行。

每个任务和最终审查仍继承不可变原始请求及此前约束。只从提示词中去除与该请求逐字相同、没有额外供应商内容块的末尾用户副本；保存的完整历史不变。规划器新增的全局约束仍放在工作者的 system 消息中。

结束控制工具继续要求状态、实际报告、未解决项；独立验证继续强制要求 `verification_passed`。没有新信息的结论、假设和证据数组可省略，与原有结果解析的默认值一致；真实工具证据始终由运行时附加。最终审查仍校验全部当前有效的计划产物引用，没有减少独立验证节点或绕过全局验收。

## 目录与审批

共享运行时识别当前原始请求中明确的工作目录限制，也可由可信调用者额外收紧。限制继承到所有子任务。文件工具及 shell 调用前检查显式绝对路径、相对越界、引用的 inline/heredoc Node 程序、本地 Node 辅助脚本及符号链接；越界调用在审批和执行前被拒绝，记录真实 denied 证据。工作者可纠正这次没有执行的输入错误，已有成功操作不重放。AI/人工安全拒绝继续作为阻塞，不能被清除为成功。

这是一层已复现路径的调用前检查，不是通用操作系统沙箱，也不能证明任意动态程序的所有运行时路径都受隔离。任意 shell 仍保留原有风险分类和审批机制；原生插件不能绕过显式目录限制。

Node 程序预检检查文件 API 的路径参数与可解析的常量、路径拼接、辅助函数和有界数组遍历，区分文件路径和日志数据。`console.log('/')` 不代表访问根目录；`d + '/answer.json'` 要按 d 的已知值解析，不能把后缀单独当作绝对路径。真正的 `fs.readFileSync('/')` 仍被拒绝。五个实际误判调用的离线回放全部通过，记录见 `fast-efficiency-v2-scope-replay.json`。

针对没有验收必要的辅助脚本清理，执行说明提示将临时程序放在工作目录内、适合时使用 Node inline/stdin，并避免为了整洁发起额外删除。用户要求的清理和真正必要的删除继续经过原审批，未打开极高风险自动审批、减少独立评审票数或改写任务授权。旧三次人工审批的具体待批命令没有保存，不能推定全部由删除导致；新测量脚本会保存完整待批参数供核对。

并行请求的取消信号优先使用运行时支持的原生 `AbortSignal.any`，继续传递所有父级取消信号；旧环境保留可释放的监听器实现，不通过提高监听器上限来隐藏警告。

## 验证与真实对照

新增 `scripts/test-fast-efficiency.mjs` 使用真实本地工具和脚本化模型，检查共享 DAG、完整证据按需读取、未知/失效引用、四个独立只读检查者和五个独立验证节点、实际错误结果的拦截、目录/引用/辅助脚本/符号链接限制、调用纠正、原有删除审批和并行取消。现有规划、验证、引擎和共享运行时回归同时保留。

全量测试通过后，使用与上一轮完全相同的四个场景、三轮配对、交替模式顺序、原始文件和提示词，启动 24 次新真实模型运行。活动期间冻结代码和提示词，不修改算法、不替换失败样本。预算护栏仍为 8,000,000 Token，未知 usage 保守预留。预先约定见 `fast-efficiency-plan.json`，数据写入独立的 `fast-efficiency-*` 文件，不覆盖旧成绩。

## 中间试验与修正

版本 1 记录了 21 次尝试，19 次成功；其后供应商返回 HTTP 402 / Insufficient Balance，活动自动停止。复杂 DAG 首轮规划由上一轮约 34 秒降至 11.76 秒，但目录预检产生五次误判，证据视图又遗漏合法传递依赖，导致额外改写、查询与模型往返，总 Token 反而上升。小证据一律间接查询也增加了简单任务的开销。不能把规划缩短当作整体收益。

完整中间数据、失败和额外报告质量问题分别保留于 `fast-efficiency-benchmark.json`、`fast-efficiency-comparison.md`、`fast-efficiency-v1-correction-record.json` 与 `fast-efficiency-v1-quality-observations.json`，不当作当前修正版的实测结论。

修正版修复上述误判、采用精确原文内联/查询切换并补齐合法祖先视图。完整 84 个测试脚本再次通过后，账户恢复，另起 `fast-efficiency-v2-*` 活动，完整重跑四场景三轮，不复用或替换中间版样本。版本 1 护栏结算 2,678,967；版本 2 护栏为余下 5,321,033 Token，合计最多 8,000,000。两者均含未知用量保守预留，不是精确账单。版本 2 的完整结果见 fast-efficiency-v2-comparison.md，保留为后续修复前的独立试验。


## 版本 2 的完整诊断与版本 3 修复

版本 2 完成 24 次尝试，21 次完整结束、20 次通过全部原始验收，得到 9/12 合格性能配对。两次 Fast 局部独立验证提出未要求的 scratch 负向测试，`rm -rf .negcheck` / `.order_check` 触发真实人工审批而中止；未开启极高风险自动批准。复杂 DAG 第 2 轮首次规划失败后取消四个已启动的只读检查者，恢复又克隆四份正确检查者，消耗 24 个 Agent 配额；最后一次恢复缺少约束头被拒绝。原始元数据不能还原首次规划失败的确切错误消息，该项不作确定归因。另有 Standard 并行第 2 轮只委派一个真实检查者，数值正确但违反四个独立检查者要求，判失败而不补跑替换。精确 JSON 断言通过 23/24，包含独立检查者数量的主验收通过 22/24。

完整工具路径/程序体复核中未识别已执行的目录越界；一次 Fast 提议列举父级试验目录被预检拒绝，实际未执行。这不构成对任意动态程序的沙箱保证。审批详情、42 项绑定工具 SHA 的原始协议/目录复核、独立外部断言都保留在 fast-efficiency-v2-*。

版本 3 只进一步修改 Fast 执行器/工作提示词及恢复协议，不修改 Standard 算法。恢复若已有全局目标可沿用原始请求与约束，也可在任何操作前显式添加约束；首次没有目标仍要求完整头，后置约束仍拒绝。首次及后续规划错误在 planning_errors 中保留，并在真实测量中脱敏导出；恢复提示提供共享已耗配额，预留未完成任务和必需最终审查的 Agent 次数，要求复用正确产物和自动恢复的只读任务，而非克隆替代。

Fast 的 run_command 增加可选 request_user_approval；在未启用原有完整授权/极高风险自动审批时，破坏性提议先作为未执行的可纠正输入返回，说明无破坏性替代及原始任务边界。确有必要的破坏性操作可带 true 请求原审批；true 不是同意，不跳过人工决定或六次自动审查。独立验证和最终审查明确避免为非交付 scratch 辅助脚本新增“验证验证器”义务，同时所有原始要求、必要边界/负向测试、工具能力及最终审查保持。必要的审批拒绝仍导致任务不能完成。

新增离线回归通过真实工具验证：可纠正破坏性提议而没有执行/人工请求，必要删除被人审否决且文件保留，已有完整授权保持生效，开启极高风险自动审批仍实际执行完整三轮各两位独立审查。还覆盖继承/缺失/后置约束头及失败检查不能放行；模型 Max 与 16,384 输出预算仍逐次断言。

用户已于 2026-11-10 选择将本次总护栏提高到 10,500,000 Token，并要求新跑完整 24 次。前两版护栏结算 6,309,567，因此版本 3 的独立上限为 4,190,433。全量回归后冻结版本 3；四场景、三轮、全部 Standard/Fast 重新调用，无复用对照、无替换失败。新数据写入 fast-efficiency-v3-*，不混合前两版。


## 版本 3 完成结果

全量 84 个本地测试脚本通过，随后冻结 22 份运行时/提示词/测量文件和 19 份计划内源码指纹，按原四场景、每场景三轮、同一 DeepSeek/deepseek-flash Max、上下文 1,000,000、输出预算 16,384 跑满 24 次新真实运行。没有复用或替换样本。Fast 12/12 完整验收通过，Standard 9/12；9 对合格性能配对全部更快，4 对减少 Token。Standard 的流水线第 2 轮及并行第 2/3 轮均因附加测试/临时清理中的真实删除提议进入人审中止，原样保留且不计为完成耗时。

相对本轮 Standard 的合格配对，中位时间节省/Token 变化为：汇总 +8.4% / +23.3%（3 对）、编码 +36.2% / -20.9%（3 对）、流水线 +28.4% / -9.8%（2 对且 Token 方向不一致）、并行 +12.6% / +99.2%（仅 1 对，不能据此确认三轮配对稳定性）。Fast 并行自身三次墙钟为 98.08、96.03、103.05 秒，保留四个真实只读检查者及五个独立验证节点。

相对上一阶段合格 Fast 的同轮历史观察，复杂 DAG 规划中位 38.60→14.38 秒（下降 62.7%），总 Token 配对变化中位 -12.1%，其中一轮仍增加 3.1%。独立验证角色 Token 中位 113,983→119,325（增加 4.7%），最终整合 66,086→42,509（下降 35.7%）。独立验证开销未实现下降，不能用规划改善替代该结论；一般稳定省 Token、50% 缩时与开放任务质量等价仍未证实。历史观察跨时间，不能将所有波动归因为代码改动。

原始固定数值/协议与目录复核共 24 份、42 项绑定 SHA 的判断已完成，全部手工待办为零。完整工具证据中未识别已执行目录越界；两次目录拒绝分别为 Fast 访问父级目录的提议与 Standard 子目录进入/返回脚本的保守拒绝，后者不能当作真实已执行违规。静态预检不解释任意 shell 控制流，也不是通用 OS 沙箱。

保留的独立检查在并行 Fast 第 3 轮发现 west 报告权重枚举的一处错误，并用正确原始记录和乘积解释；最终主审又发现自己的加权汇总表达式算成 145，修正后重跑得 692。所有失败与成功记录保留，请求的区域数值和原 answer.json 始终正确。证据见 fast-efficiency-v3-quality-observations.json；这些属于实际纠错，未降低固定验收或替换失败样本。

最终本活动供应商已报 3,371,760 Token，usage 无缺失；含探测的护栏为 3,371,830。本次三版合计护栏结算 9,681,397，未超过用户确认的 10,500,000；早期未知用量保守预留保留，不等同精确账单。完整结果见 fast-efficiency-v3-comparison.md、summary.json、quality.json、completion.json 及对应原始执行记录。没有额外启动付费补跑。
