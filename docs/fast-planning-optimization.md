# 规划开销优化

上一轮同模型 Max 档位的真实对照中，Fast 的规划请求耗时 34.25 秒，输出 4,731 Token，其中接口报告推理 Token 为 3,985。最终只有一个工作任务，规划器仍重新生成了一组较长的任务、验收和报告契约。

本轮调整规划信息的表达和传递方式，保持模型、思考档位、上下文容量、输出预算、工具审批、独立验证和外部验收要求不变。

## 原始请求声明

对适合由一个工作节点负责的完整请求，规划器可返回：

```json
{"type":"single","access":"exclusive"}
```

运行时把不可变的原始请求逐字放入任务目标和验收标准，并保留此前适用的用户约束与完整历史。该声明不能提供替代目标、替代验收、其他依赖或验证角色，因此不能用一份较短但有遗漏的模型改写替换原始要求。

展开后的任务仍经过原有调度器校验，执行普通工作节点、独立 `.verify` 和强制全局审查。访问类型必须明确，路径、审批和父级限制照常生效。声明不表示任务已完成，也不会跳过实际执行和验收。

单节点声明只用于没有既有任务的新运行；失败恢复仍采用保留状态、已验证产物和显式修复的 DAG 协议。复杂依赖、独立交付、额外集成检查及明确要求的独立 Agent 继续使用 DAG。

## 其他调整

- DAG 传输可省略不影响语义的默认字段，例如空依赖、空版本绑定和调度优先级。目标、验收标准、输出契约和访问类型仍须明确，最终经过原调度器完整校验。旧完整 JSONL 仍兼容。
- 初始规划不携带完整恢复操作说明；恢复请求按需加入 `assets/fast-replanner.txt`，不改变恢复行为。
- 只有末尾纯文本用户消息与不可变请求完全相同时，才从规划历史中移除这一个重复副本；其他历史、不同文本及原始供应商内容块都保留。传给工作节点的历史不变。
- 规划预算提示保留完整共享上限和当前计数，省去根运行 ID、界面等无关快照字段。实际共享配额仍由 TaskRuntime 强制执行。
- 初始规划策略文本由 5,329 字节变为 3,222 字节。代码允许单行声明，但没有降低 Max 档位或 16,384 Token 输出预算；真实耗时和实际 Token 变化以本轮模型数据为准。

## 回归与实测

新增 `scripts/test-fast-planner.mjs` 覆盖原始多语言验收逐字保留、此前约束、明确权限、非法验收覆盖、流式启动、必要检查失败、历史去重边界、旧 DAG 以及失败恢复。原引擎和验证合并的定向回归已通过。

本轮完整测试清单和源码指纹写入 `fast-planning-test-results.json`。真实配对沿用 `DeepSeek/deepseek-flash`、`Max`、多模块编码场景、原始四条测试断言和 16 组独立公式检查；质量脚本为 `scripts/audit-fast-live.mjs`。报告、时间线和代码产物分别保存，不覆盖上一轮数据。

## 本轮真实对照结果

全量 82 个测试脚本通过后，完成了一次新的真实配对：Standard 56.20 秒、115,824 Token；Fast 45.12 秒、113,519 Token。Fast 本轮耗时减少 19.7%，Token 减少 2.0%，规划请求为 1.68 秒、126 输出 Token。模型仍为 deepseek-flash / Max，输出预算均为 16,384，完整原始验收保留；两边均无重试或缺失 usage。

独立质量复核的原始四条断言和 16 组公式检查全部通过，功能代码逐字节相同。数据、适用范围和复现命令见 `docs/fast-planning-live-comparison.md`；这是单场景一次配对，历史 Fast 数据仅作参考。

## 后续多场景重复对照

冻结本轮规划优化后的运行时代码，使用同一模型和 Max 档位，对四个原有任务场景各运行三轮 Standard/Fast。共 24 次新运行，21 次完整结束，20 次通过全部质量验收，形成 8 对合格性能配对。编码三轮均更快但优势波动大，其他任务未确认三轮一致提速；8 对中 7 对 Fast Token 更多。详细数据与证据见 [fast-stability-comparison.md](fast-stability-comparison.md)。此前单次编码的 19.7%/2.0% 是历史观察，不能外推为稳定收益。
