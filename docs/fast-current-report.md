## 逐轮数据与统计

两个版本各有 4 个场景，每个场景有 5 组全新的 Standard/Fast 配对。分场景表从左到右显示 5 次观测和这 5 次观测的统计量。

- **缩时**为 `100 × (1 − Fast 秒数 / Standard 秒数)`，正值表示更快。**Token 变化**为 `100 × (Fast 总 Token / Standard 总 Token − 1)`，负值表示节省。先算同轮比值，再对 5 个比值统计。
- **平均数**为算术平均数。**样本方差**为 `Σ(xᵢ − 平均数)² / (n − 1)`，分场景取 n = 5，全部配对汇总取 n = 20，剔除严格串行的子集取 n = 15。耗时方差的单位为秒²或毫秒²，百分比的方差为百分点²，Token 方差为 Token²。计算使用原始精度，最后才舍入。
- **1/0** 表示是/否。Token 判定使用未舍入的耗时与用量，Fast 更快时允许总 Token 为 Standard 的 2 倍，持平或变慢时为 1.05 倍。二元指标的平均数即该场景的通过比例。先行模式是类别，统计栏用「—」表示不适用。 阶段表中某角色在一轮内没有发出模型请求时，次数和 Token 都记为 0。

展开各场景的分项表可查看输入、输出、缓存、推理、模型请求、工具、调度与各阶段用量。同一单元格内的两个数分别计算中位数、平均数、方差。缓存输入包含在输入中，推理 Token 包含在输出中。吞吐量用总 Token 除以墙钟秒数。工具耗时累计非委派工具的执行时长，验证请求耗时累计该角色的模型请求时长，重叠区间可能重复计时。预算计入量包含该组两次任务和一次连通性探测。

两版共 80 次执行，逐次运行成功、数值正确、完整验收及用量完整均为 1，各自在每个场景、每种模式下中位数和平均数为 1，方差为 0。任务重试、审批等待毫秒数、审批中止、派发前被预算阻止的请求和缺失 usage 的请求逐次均为 0，中位数、平均数、方差也均为 0。手工审批等待为 0，执行用时与墙钟用时相同。Standard 未记录 Fast 调度耗时。
