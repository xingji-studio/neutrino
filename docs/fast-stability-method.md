# 多场景三轮真实对照方法

本轮冻结上一轮规划优化后的 Agent 实现。选择多源资料汇总、多模块编码、严格顺序文件流水线、四路独立并行分析四个现有夹具，每个场景三轮 Standard/Fast 配对，共 12 对、24 次新运行。输入、提示词和外部验收标准沿用现有夹具，不复用历史成绩。

模型固定为 DeepSeek/deepseek-flash，Max 档位，输出预算 16,384；共享任务配额不变。每次运行使用独立会话和临时目录。配对顺序按场景索引和轮次交替，全组各有六对 Standard 先运行、六对 Fast 先运行。缓存仍按真实供应商行为工作，命中 Token 单独记录。

活动总护栏为 800 万 Token；未知用量保守预留不当作精确账单。运行前及每次新任务前检查运行时代码与提示词指纹；中途不修改算法以改善成绩。原始数据、失败、重试及不完整样本均保留。

## 质量

- 所有场景核对输入未变、精确 JSON 输出、任务结束状态及产物哈希。
- 资料汇总检查三份原始资料、数字求和及最终引用，并审阅实际文件读取/Node 执行证据。
- 编码检查原始四条断言、16 组公式输入、导出类型、模块独立性以及 JSON 与实际函数的一致性。
- 顺序流水线检查每个保存的中间文件及数值关系，并审阅实际命令/程序，核对后续计算读取已写入的前驱文件。
- 并行分析独立重算四份数据，核对四个不同且实际受只读策略约束的检查者；每个只读检查者只读取其自身数据。另审阅协调者执行的 Node 代码，确认对原始数据和检查者报告的验证发生在整合前。

纯值正确不能自动通过执行顺序或协调行为检查。需要审阅的检查先标记为 pending；审阅结论绑定对应工具证据文件哈希及工具 ID，然后再计入最终质量结果。元数据 JSONL 继续只记录时序、数量和哈希；另存的 tool-evidence.json 是本次自有夹具的审阅材料，凭据会被排除或遮蔽。

## 统计口径

每个场景展示三个配对的完整数据、两侧中位数/范围、每轮提速与 Token 变化，以及 Faster/Lower-token 的轮数。只有两侧完成且通过全部质量检查的配对才有合格提速率；失败样本仍显示在运行数、成功数、质量通过数和原始耗时中，不补跑替换。

“观察到一致提速”指该场景三个合格配对均为 Fast 耗时较少；“观察到一致 Token 减少”还要求三对 usage 完整且三个配对均减少。细小正差异也只记为观察方向，不自动认定具有实际或统计意义。三次重复不足以估算可靠 P95、建立总体稳定性或证明一般质量等价。

只有全部 12 对合格，才给出跨场景的等权几何平均时间比。网络失败和退避保留在实测时间中；缺失 usage 会阻止完整 Token 结论，不按零计算，也不从墙钟扣除。主要结论按场景报告。

冻结配置、源码指纹和预检见 `fast-stability-plan.json`；原始运行见 `fast-stability-benchmark.json`，最终数据、审阅记录和统计结果分别保存。
